# Обложки, иллюстрации и происхождение медиа

Изображение помогает понять материал, заметить деталь или почувствовать шутку. Оно должно работать с конкретным текстом. Наличие картинки рядом с текстом само по себе не решает задачу.

## Обложка

Один ясный предмет и один основной визуальный акцент. Заголовок и обложку проверяем вместе, в том числе в размере карточки на телефоне. Читатель должен увидеть, о чём материал.

Для устройства полезен сам предмет; для приложения — понятный результат или реальный интерфейс; для обзора — характерная демонстрация. Оригинальная редакционная иллюстрация тоже подходит, если честно передаёт тему.

Проверяйте:

- правильный продукт и бренд: чужой логотип не заменяет изображение темы;
- отсутствие случайных надписей `AI`, `GPT`, псевдокода, плат и процессоров ради декора;
- отсутствие мусорного мелкого текста, лишних значков, неверных рук и предметов;
- понятную композицию, читаемый текст и аккуратный кроп;
- разнообразие соседних публикаций: один и тот же логотип или шаблон быстро становится незаметным.

Если композиция хорошая, исправляйте конкретный дефект. Не перегенерируйте одобренное изображение целиком без причины.

## Иллюстрация внутри материала

Показывает действие или результат именно в том месте, где о нём говорится. Скриншот должен быть достаточно крупным; выделение фрагмента полезнее нечитаемого полного рабочего стола. Не подменяйте кадры результата заставкой ролика и портретом ведущего.

Для статьи часто нужны иллюстрация предмета ближе к началу и несколько кадров по ходу объяснения. Это не числовая квота: каждый кадр должен выполнять свою работу.

Подпись сообщает, что видно и на что обратить внимание. Не пишите «скриншот из видео» вместо объяснения происходящего. Источник можно указать рядом коротким кредитом.

## Медиа-карта

Для каждого элемента в `media.md` запишите:

| Поле | Что указать |
| --- | --- |
| ID и роль | Например `cover`, `frame-01`; обложка, шаг, результат, шутка |
| Место | После какого смыслового блока вставить |
| Файл или источник | Относительный путь разрешённого файла либо публичная ссылка; у видео — таймкод |
| Происхождение | Своя генерация, свой скриншот, кадр чужого видео, официальное фото, сторонний мем и т. п. |
| Автор и использование | Кредит, лицензия/разрешение/другое основание; что ещё требует выяснения |
| Обработка | Обрезка, перевод, выделение детали, генерация, существенная ретушь |
| Подпись | Точный читательский текст либо «подпись не нужна» |
| Проверка | Какой окончательный файл открыт, какие дефекты устранены, что осталось |

Публичная доступность картинки не равна разрешению на её повторное размещение. Ссылка на автора не заменяет разрешение. Если основание неизвестно, укажите это и не добавляйте файл в открытый репозиторий. Не нужно выдумывать юридический статус или универсальное разрешение для всех скриншотов.

Сгенерированная редакционная иллюстрация не должна выглядеть как доказательство реального теста, точный интерфейс или документальное фото события. Способ создания фиксируется в карте. Информация для редактора, обязательная маркировка площадки и подпись для читателя — разные вещи.

## Финальная визуальная проверка

Откройте точные файлы, которые будут переданы в выпуск. Посмотрите на телефонном размере и в полном размере. Проверьте текст, анатомию, последовательность панелей, логотипы, границы кадра и соответствие теме. После исправления откройте новый файл снова.

Нельзя писать «медиа проверены», если просмотрен только промпт, миниатюра предыдущей версии или список файлов. В `review.md` укажите реально просмотренные версии.

Для Дзена после загрузки проверьте **и картинки в теле, и выбранную обложку карточки**, затем окончательный предпросмотр. Если исправлена обложка, убедитесь, что площадка использует новую версию, а не прежний файл. Это часть передачи в выпуск, которой один коммит на GitHub не заменяет.
